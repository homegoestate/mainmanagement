## 身分共用的精確意思

員工可有同一個內部人員識別與伺服器維護的 provider 對應，但各資源各自驗證登入憑證、權限與撤銷。Firebase ID token 不能不經適當交換／驗證就當成 Supabase JWT。LINE 顯示名稱、表單傳入的 User ID、QR 專案參數、Sheet 編輯權，也都不能代表員工或案件授權。

至少分開三種 actor：員工、建商窗口、承購戶；一人兼具多身分時，仍按當次上下文與授權資料範圍作業。員工主管不自動取得所有建商／客戶資料，建商也不因持有建案代碼取得整案個資。撤銷身分須檢查各服務既有 session，不只把選單隱藏。

宏國地政｜易丞地政是共同品牌，楊明宗與楊翊晟目前各自獨立執業。案件歸屬、法定受任、收入與紀錄須保留 responsible_practitioner / legal_entity 邊界；共用品牌不代表所有資料可互相任意存取。

## 應共用的契約，與應分開的資料

| 共用契約 | 要求 |
|---|---|
| 永久識別 | 建商、建案、戶別、承購人、案件、執業者各自永久 ID；人看得懂的代碼（例如 MHR）只作標籤，不作唯一外鍵 |
| 欄位主責 | 契約戶別由核定清冊；客戶自報資訊先進收件區；正式登記狀態由承辦端決定。外部更新不能直接覆蓋內部已核實資料 |
| 同步事件 | event_id、source_system、actor_id、entity_id、expected_version、occurred_at、review_status；事件內容最小化，不廣播整案 JSON |
| 重複與衝突 | source_system + event_id 唯一限制；expected_version 原子檢查；衝突進人工佇列，禁止最後送出者覆蓋所有資料 |
| 失敗復原 | 待同步／成功／待核對／失敗可辨識，有重試上限、冪等與可追蹤稽核；對外畫面不得把未核實當已完成 |

假勤、薪資、客戶收件、案件內部底稿與建商報表保留各自權限及儲存責任，不整包複製成人人能讀的共用主檔。不先把四個前端互相寫入，再補權限。

## 對目前 PR 的影響

保留兩庫資料與既有 UID；驗證／授權核心可供日後可信服務使用。先不替 LINE 發員工 token，不加正式同步或跨建商開放，不修改原案件。新增後端部署位置需同時評估目前兩庫與已存在的 Supabase／Apps Script 能力，不能僅為一個登入補丁就把長期架構綁死。

`backend/INTEGRATION.md` 的 Firebase Functions 是可部署選項而非已核定平台；Blaze 計費與跨專案 IAM 都未啟用。若既有可信後端可安全承載，優先比較其維護、資料隔離、授權、故障及成本。正式跨系統工程另以備份可還原、匿名風險排除、既有讀寫通過，作為啟動門檻。
